# dsh-futures-radar · 期货趋势雷达

[English](README.md) | **中文**

DSH 插件：基于**加权指数日线**的商品期货趋势策略监控。
盘后算出次日任务清单，盘中盯着实时价，在**触发 / 收盘确认 / 止盈 / 止损**时提醒，并把每条提醒写入日志供复盘。

> 早期“30 秒量价爆发”逻辑经回测证明是事后确认（各持有窗口全部负期望），已整体移除。
> 当前版本只保留趋势策略。

## 策略一句话

- **主策略**：55 日通道突破 + MA20>MA60 + 量比≥1.2 + TRIX(12) 同向，次日开盘入场；
  出场：**5% 固定止损** / 跌破 MA20 / TRIX 反向交叉 / 持有 40 天。
- **辅助**：暴跌右侧多（近 10 日跌≥15% + 上穿 MA10 + 仍在 MA60 下方）。
- **组合层**：并发 8、同板块 2、按量比降序、同品种反手合并。

信号在**东方财富加权指数**（`159.<品种>fi`）上计算，规避主连换月跳空；加权不可交易，实际成交在次日开盘的主连。

**回测口径与已知缺陷见 [docs/trend-strategy.md](docs/trend-strategy.md)**：
SAR 止损版经前视修正后 PF 1.14（原策略 1.39），已撤回，默认固定止损；
组合级数字见文档 §9.0/§9.1（加权 +6.7% / 主连 +6.2%）。

## 提醒

| 类型 | 条件 | 级别 |
|---|---|---|
| `trigger` 触发 | 现价越过 55 日高/低点（盘中预警，需收盘确认） | 普通 |
| `stop` 止损 | 持仓现价触及止损价 | 强 |
| `tp` 止盈 | 持仓达到 2R（**仅提示，回测出场不含 2R**） | 琥珀 |
| `confirm` 收盘确认 | **收盘后**复核：收盘价越过通道且量比/TRIX 全部满足；提醒里给出具体入场窗口（今晚 21:00 夜盘 / 次日 09:00 早盘）；是否开仓看次日任务（通过组合约束为「强」，被拒为「普通」） | 强/普通 |

同一品种 + 同一类型 + 同一交易日只提醒一次，避免刷屏。

**⚠️ 触发 ≠ 入场**：`trigger` 只是盘中越过通道，收盘可能收回，或被量比/TRIX 拦下；
`confirm` 只是对盘中信号的收盘复核，**不直接生成开仓任务**；次日是否开仓以
CLI/宿主的「次日任务」为准（同一套组合约束：并发 8、板块 2）。设置页的
「收盘确认」会逐条标注「已过组合约束」或「不开仓 + 原因」，并列出未确认品种
（收盘收回、量比不足、TRIX 未确认）。

## 复盘日志

所有提醒写入 `~/.dsh/futures-radar/alerts.jsonl`（每行一条）：

```json
{"at":1762...,"type":"trend","kind":"trigger","code":"RB0","name":"螺纹","dir":"up",
 "price":3135,"level":"normal","text":"触发：突破 55 日高点 3130.00","day":"2026-11-10"}
```

```sh
# 最近 30 条
jq -r 'select(.type=="trend") | [.day,.kind,.code,.name,.price,.text] | @tsv' \
  ~/.dsh/futures-radar/alerts.jsonl | tail -30

# 某品种的全部提醒
jq -r 'select(.code=="RB0") | [.day,.kind,.price,.text] | @tsv' \
  ~/.dsh/futures-radar/alerts.jsonl
```

## 仓位计算器（设置页）

在设置里填两个数：

| 字段 | 含义 |
|---|---|
| **账户权益** | 期货账户的**动态权益**（上日结存 + 当日盈亏 + 出入金），不是可用资金 |
| **风险/笔** | 默认 0.6%，即每笔最多亏权益的 0.6% |

插件按下面公式算手数并显示在持仓/确认信号旁：

```
止损距离 = |入场价 − 止损价| / 入场价（固定止损下恒为 5%）
仓位比例 = min(0.6% ÷ 止损距离, 12%)
手数 = 权益 × 仓位比例 ÷ (入场价 × 合约乘数)   （向下取整）
```

合约乘数在 `data/multipliers.json`，其中 `unverified` 列表（BZ/PL/AD）请按交易所公告核对。

> 当前默认固定 5% 止损，所以 `0.6% ÷ 5% = 12%`，仓位恒等于 12% 上限——计算器的作用是
> 把 12% 名义仓位换成**手数**，不是做动态风险平价。

## 命令行

```sh
npm run trend                                    # 盘后扫描 61 个品种，输出次日任务
node scripts/trend-scan.mjs --json               # 机器可读
node scripts/trend-scan.mjs --only=RB,M --date=2026-11-09
```

默认输出（只算监控起点之后）：

```
监控起点 2026-11-10：历史持仓 5 个不计入（--all 显示全部）
── 当前持仓（组合层约束后 0/8）──
  （空仓）
── 明日任务 ──
  （无）
```

加 `--all` 才会显示历史持仓（如 AG0/SN0 等）及其平仓任务。

## 数据与限制

- 数据源：东方财富加权指数（日线）、新浪实时快照。
- 日线缓存：`~/.dsh/futures-radar/trend-daily.json`，最多 30 分钟刷新一次。
- 已知限制：加权不可交易；止损按盘中触发、跳空按开盘价成交；
  一字板未特殊处理；2R 只是提示，实际出场靠 MA20/TRIX/固定止损/到期。
- 价位换算：提醒位用「前结算 / 加权前收盘」把加权价位折算到主连，比价异常（超出 0.8–1.25）时退回 1:1；
  历史持仓沿用当前比价近似（未保存建仓日比价），旧仓的止损/止盈提醒也会按这个近似价判断。
- 收盘确认：以「最近一个已收盘交易日」为目标，15:15 之后补做（21:00 后、周末打开也会补做当天/上一交易日）；
  要求日线在 15:10 后刷新且 90% 品种的末根是目标日，否则显示「确认待定」。
  确认结果只是信号复核，不直接生成开仓任务；同一交易日只确认一次，重启不会重复推送。
- 交易日归属：21:00 起的夜盘算**下一个交易日**（周五夜盘算下周一），00:00–02:30 仍属当天；
  提醒去重、收盘确认、日志日期都按这个交易日，不再按自然日。节假日需人工核对。
- 监控起点：`~/.dsh/futures-radar/monitor-start.json`，只监控该日之后的新开仓；
  历史持仓不参与止损/止盈提醒，`--all` 可查看全部。
- 部署前提：时间判断（15:10/15:15/21:00、交易日归属）按北京时间，请确保机器在 UTC+8 时区运行。

## 安装

需要 Node.js 18+，以及带 `webServer` 服务的 DSH 版本。

1. 把本包链接或复制到 profile 的 `node_modules`：

   ```sh
   ln -s /path/to/dsh-futures-radar ~/.dsh/profiles/desktop/node_modules/dsh-futures-radar
   ```

2. 在 profile 的 `cordis.patch.yml` 中注册 bundle：

   ```yaml
   - insert:
       - id: futures-radar
         name: 'dsh-futures-radar'
   ```

3. 重启 DSH（或切换插件开关），在设置页启用。
